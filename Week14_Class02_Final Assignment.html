Final Project Guidelines

This is the final project for the Machine Learning and Deep Learning certification program. Each student or team must build a complete, reproducible ML/deep-learning project, track training with MLflow, document the workflow clearly, and submit the work through GitHub.

Certification requirement: This final project is mandatory for completing the certification requirement. Students who do not submit a valid final project will not satisfy the course completion requirement.

Strict Final Deadline

25 June 2026

The certification program ends on 26 June 2026, so this deadline will be strictly maintained. There will be no extension after 25 June 2026.

Review notice: There may be a project review on 26 June 2026. Students must be ready to explain their code, prediction pipeline, Docker setup, MLflow runs, results, README screenshots, and final repository structure.

Choose One Project Domain

Pick one domain from the list below. Your implementation must be realistic for the selected domain and should include a clear dataset source, training pipeline, evaluation, and demonstration. In addition to training, every project must develop a prediction pipeline with a UI where a user can upload sample input data such as an image, Excel/CSV file, written text, video frame, or other suitable test sample. The model must process the uploaded sample and show the prediction/output clearly. This prediction app must be served using Docker.

AI-powered fraud detection system Example: upload a transaction CSV/Excel file and show whether each transaction is normal or suspicious, with fraud probability and top risk indicators.
Autonomous driving perception system Example: upload a road image or short video frame and detect lanes, vehicles, pedestrians, traffic signs, or road-scene classes.
Medical image analysis with deep learning Example: Multi-Class Brain Tumor Classification Using Transfer Learning on MRI Images. Upload a sample MRI test image and show the predicted tumor class with confidence.
NLP-powered chatbot for customer support Example: type or upload customer queries and show generated answers, detected intent, confidence, and escalation recommendation.
Reinforcement learning for stock market prediction Example: upload historical stock-price CSV data and show the model's suggested action such as buy, sell, hold, expected reward, and portfolio simulation output.
Fine-tuned Transformer-based text summarization model Example: paste or upload a long article/document and show an abstractive summary, compression ratio, and key points.
Hyperparameter optimization for large-scale deep learning models Example: upload or select a training configuration and show the best hyperparameter set, comparison table, MLflow runs, and final model result.
Prediction app requirement: The final project is not only a training notebook. It must include a usable prediction/demo application with an upload interface and visible model output. The app can be built with Streamlit, Gradio, FastAPI + frontend, Flask, or another suitable UI/API stack, but it must be runnable through Docker.

Core Requirements

1. GitHub submission

  • The full project must be submitted as a public GitHub repository.
  • The repository must contain clean, runnable source code.
  • The repository must include a complete README.md.
  • Commit history should show meaningful progress, not a single last-minute upload.

2. No data in repository

  • Do not include datasets in GitHub.
  • Your code must automatically download or fetch the required data into a local data/ folder.
  • Add data/ to .gitignore.
  • The project must be runnable after cloning by following the README instructions.

3. MLflow training tracking

  • Training must use MLflow to track training progress.
  • Log hyperparameters, metrics, model artifacts, and relevant plots/files.
  • Run at least two experiments or training runs with different settings.
  • The README must include screenshots of the MLflow experiment page.

4. Demonstration and screenshots

  • The README must include necessary screenshots showing how the system works.
  • Include screenshots of prediction/inference output, UI/API response, or evaluation results.
  • Include commands for training, inference, and launching any app/API/notebook.
  • Explain limitations and possible improvements.

5. Use course techniques

  • The project must apply techniques learned during the course, where relevant to the selected domain.
  • Examples include data preprocessing, model training, transfer learning, Transformers, hyperparameter tuning, MLflow experiment tracking, model evaluation, Dockerization, API/UI serving, and reproducible project structure.
  • The README must explicitly mention which course techniques were used and where they appear in the project.

6. Dockerized prediction app

  • The prediction/demo app must run using Docker.
  • The Dockerized app must expose a UI or API for uploading sample input data and showing the model output.
  • The README must include docker build and docker run commands.
  • Provide screenshots of the Docker-served prediction app working successfully.

7. Final project report

  • Students must write a final report describing the complete project work.
  • The report should cover introduction, problem statement, dataset, methodology, MLflow experiments, results, prediction pipeline, Docker setup, limitations, and future work.
  • Use the final report template available at www.rb.gy/lie1pp. The template file name is SICIP_TEMPLATE_final_report.
  • The completed report must be included in the GitHub repository.
Important final report submission rule: Prepare the report using SICIP_TEMPLATE_final_report, submit the final report in PDF format, and name the PDF exactly as SICIP_NAME_ID.pdf.

Expected Repository Structure

You may adjust the structure based on your domain, but the repository must remain clean and reproducible. The data/, cache files, virtual environments, and large generated artifacts must not be committed. However, mlruns/ should not be ignored because MLflow experiment evidence is required for evaluation.

final-project/ |-- README.md |-- final_report.md |-- requirements.txt |-- .gitignore |-- Dockerfile |-- src/ | |-- data_download.py | |-- train.py | |-- evaluate.py | `-- predict.py |-- app/ | `-- app.py # Streamlit/Gradio/Flask/FastAPI prediction UI |-- notebooks/ | `-- exploration.ipynb |-- configs/ | `-- config.yaml |-- mlruns/ | `-- ... # MLflow runs must be included |-- screenshots/ | |-- mlflow_runs.png | |-- training_result.png | |-- docker_app_running.png | `-- demo_output.png |-- models/ | `-- .gitkeep |-- data/ | `-- .gitkeep # folder exists, actual data is downloaded locally `-- artifacts/ `-- .gitkeep

README.md Must Include

Project overview: selected domain, problem statement, and expected output.
Dataset: source link, description, download method, and why the data fits the task.
Setup: Python version, dependency installation, environment setup, and run commands.
Data fetching: clear command showing how data is automatically downloaded into data/.
Training: command to train the model and explanation of important hyperparameters.
MLflow: how to start MLflow UI, screenshots of training runs, and explanation of logged metrics.
Course techniques: list the course techniques used, such as transfer learning, Transformers, HPO, Docker, MLflow, API/UI serving, or evaluation methods.
Evaluation: metrics, plots, model performance, and interpretation of the results.
Docker prediction app: Docker build/run commands and instructions for uploading sample input data to the app.
Demo screenshots: screenshots proving that the Docker-served prediction app works end-to-end.
Limitations: known weaknesses, assumptions, failure cases, and possible future improvements.
Team contribution: if done in a team, clearly state each member's contribution.
Final report: include a completed final project report in the repository. Template: www.rb.gy/lie1pp.

Suggested Commands

Install dependencies: pip install -r requirements.txt
Download/fetch data: python src/data_download.py
Start MLflow UI: mlflow ui --host 0.0.0.0 --port 5000
Train the model: python src/train.py --config configs/config.yaml
Evaluate the model: python src/evaluate.py
Run prediction/demo locally: python src/predict.py --input path/to/sample
Build Docker image: docker build -t final-project-app:1.0 .
Run Docker prediction app: docker run -p 8501:8501 final-project-app:1.0

GitHub and Data Policy

  • The GitHub repository must be public and accessible during evaluation.
  • The project must include a .gitignore file that excludes data/, __pycache__/, virtual environments, checkpoints, and large generated files.
  • Do not ignore mlruns/. MLflow run folders should be included so reviewers can inspect training parameters, metrics, artifacts, and experiment history.
  • Do not commit raw datasets, downloaded data, private credentials, API keys, or large model artifacts unless explicitly required and small enough for GitHub.
  • If a model artifact is too large, document how to regenerate it by running the training script.
  • The code should be designed so that a reviewer can clone the repository, install dependencies, run the data-fetch script, train/evaluate, and reproduce the key results.

Minimum Acceptance Criteria

  • A public GitHub repository with clean, organized source code.
  • Automatic dataset fetching into a local data/ folder.
  • No dataset committed to the repository.
  • Training tracked using MLflow with visible logged parameters and metrics.
  • A README with screenshots showing MLflow tracking and system output.
  • A Dockerized prediction app with an upload interface for sample data.
  • README explanation of course techniques used in the project.
  • A completed final project report using the template from www.rb.gy/lie1pp.
  • Clear instructions to run the project from a fresh clone.
  • Submission before 25 June 2026.
